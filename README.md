# PromVector Agent

Отдельное настольное приложение для чтения промышленной телеметрии на компьютере предприятия. Агент нормализует данные, сохраняет их в локальной очереди SQLite и отправляет напрямую в PromVector по HTTPS. Интерфейс PySide6 и режим командной строки работают с одной конфигурацией.

| Источник | Возможности |
| --- | --- |
| OPC UA | Чтение заданных Node ID, подписка на изменения, качество и исходное время, защищённое подключение с закреплённым сертификатом |
| Modbus TCP | Чтение заданных holding/input-регистров, целые числа и числа с плавающей точкой, порядок слов |
| CSV и JSON | Импорт выбранного файла или наблюдение за выбранной папкой, проверка схемы и защита от повторного импорта |
| PostgreSQL и SQLite | Опрос разрешённых запросов в режиме чтения, идентификация строк и проверка результата |
| Симулятор | Температура, давление, обороты, вибрация и режим работы с маркировкой тестовых данных |

Gemini включается отдельно и анализирует только текст, который оператор явно разрешил отправить. Ответы хранятся отдельно от измерений. Интерфейс расширения для SCADA/MES описан в [руководстве](docs/operations.md).

## Запуск из исходников

Понадобятся Python 3.12 и uv.

```sh
uv sync --locked
uv run promvector-agent
```

1. Откройте **Источники**, добавьте **Симулятор** и включите сбор. Локальный режим доступен сразу. Данные видны в **Мониторинге**.
2. Для работы с центральной платформой задайте ID предприятия и HTTPS-адрес в **Настройках**. Администратор бэкенда выдаёт токен для ID, показанного в **Обзоре**.
3. В разделе **Связь** выполните регистрацию, затем проверьте HTTPS. Записи, собранные при настроенном адресе и недоступном бэкенде, синхронизируются автоматически. Настройте разрешённые источники и сопоставления метрик с кодами датчиков.

Центральному PromVector требуется отдельное обновление REST API. Инструкция содержит проверенную базовую миграцию, процедуру выдачи и отзыва доступа и схему обмена. [Интеграция с центральным PromVector](docs/integration.md)

## Установка и эксплуатация

[Сборка для Windows, macOS и Linux, автозапуск, хранилище и удаление](docs/operations.md)

```sh
uv sync --locked --extra test
uv run ruff check promvector_agent scripts backend-integration tests
uv run pytest -q
```

Стандартные тесты используют локальные OPC UA и Modbus TCP серверы. Отдельный тест проверяет цепочку «Симулятор → SQLite → HTTPS → существующий FastAPI → PostgreSQL» на копии бэкенда с миграцией. [Настройка сквозного теста](docs/integration.md#сквозной-тест)
